# Project Stages & Document Master Plan — 00–99

Status: rancangan struktur disepakati; isi setiap output dan subbab menunggu review satu per satu.
Tanggal: 20 Oktober 2026.
Dokumen kerja bersama, dapat diedit melalui repository. Bukan persetujuan atas isi teknis.

## Prinsip

- Sepuluh stage 00–90 menggantikan pengelompokan KO–HO secara bertahap. Kickoff menjadi dasar awal; stage lain dapat berjalan paralel mengikuti dependensi.
- x1–x8 adalah kelompok form, pekerjaan dan output pendukung, bukan kewajiban membuat delapan file. Satu kategori dapat mempunyai beberapa record/paket/area/periode.
- x9 adalah dokumen final untuk kompilasi, keputusan dan persetujuan. x9.01 dst. adalah subbab dalam dokumen tersebut.
- Katalog master bukan checklist wajib semua proyek. Pilih Required / Optional / Not Applicable sesuai scope.
- Planning → Stages mengatur scope, PIC, target, bobot dan kebutuhan deliverable.
- Work → Tasks & Deliverables menjalankan task, mengisi form dan menyusun dokumen final.
- Documents menyimpan hasil terbit, register lampiran dan versi. Tidak ada pengisian konten ganda.
- Form/narasi dikompilasi ke badan final. Gambar, model, perhitungan dan berkas besar tetap sebagai output tersendiri yang ditautkan/ditambahkan sebagai lampiran.
- Tugas biasa tidak wajib menghasilkan dokumen. Perhitungan tetap bisa menjadi prasyarat wajib meski bukan output utama klien.

## Lifecycle yang dituju

Isi form → Save Draft → Preview → Ajukan persetujuan → Approved → Publish V1 (Rev 00).

Create Revision dari V1 → draft pada editor yang sama → edit → persetujuan → Publish V2 (Rev 01).

- Save Draft tidak membuat versi terbit; Export hanya mengunduh.
- Paket terbit menyimpan snapshot isi, keputusan dan versi lampiran. Perubahan sumber tidak mengubah paket lama.
- Perubahan sumber memberi Needs Review pada output turunannya; tidak otomatis menyetujui/menerbitkan ulang.
- Persetujuan bisa per paket, area, sistem atau periode, dengan batas cakupan dan outstanding items yang jelas.
- Laporan periode baru berbeda dari revisi laporan periode lama.

## Cara review

Untuk setiap kode, tentukan: tujuan; jenis output (form/perhitungan/file/register/final); field dan validasi; sumber data; prasyarat; PIC/reviewer/approver; wajib/opsional; lampiran; tujuan kompilasi; aturan revisi.

Penanda review berikut adalah checklist pembahasan katalog, bukan status selesai pekerjaan proyek. Folder dan subbab di aplikasi masih merupakan tempat yang disiapkan, bukan dokumen yang sudah diterbitkan.

## Migrasi dan batas implementasi saat ini

- Tahap ini menyiapkan katalog dan tempat review pada Documents, belum mengganti data KO–HO atau memindahkan record lama.
- Kode yang sudah dipakai tetap dipertahankan. Label baru tidak berarti konten lama telah direklasifikasi dengan benar; audit file lama sebelum migrasi.
- Form contoh PIF, CDB, SSR, FST, SFP, SPK, PKD tetap ditempatkan pada 01, 02, 03, 04, 05 dan 08; pemetaan field/kompilasinya akan direview.
- Alur approval, kompilasi dan versi immutable di atas adalah target pengembangan, bukan klaim fitur sudah selesai.
- Struktur aplikasi: `constants/projectDocumentCatalog.json`. Sesudah perubahan hasil review, sinkronkan file tersebut dengan Markdown ini.

## Urutan pekerjaan berikutnya

1. Review 01–08 beserta struktur final 09.
2. Tetapkan field spesifik, data Information yang dipakai ulang dan peta kompilasi.
3. Selesaikan satu alur penuh: draft → persetujuan → publish → revisi.
4. Validasi pada proyek nyata, kemudian lanjut 11–19 dan stage berikutnya.
5. Migrasikan KO–HO setelah pemetaan dan retensi data lama disetujui.
